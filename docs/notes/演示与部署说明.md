本文档记录从"用户真实使用场景"出发走查后修复的问题、容器部署方式与演示步骤。

## 一、本地 / 容器启动方式

### 方式 A：Docker Compose（推荐，与生产形态一致）

```bash
docker compose up -d --build mysql redis backend frontend
# 可选 kafka 模式：docker compose up -d kafka  并在 .env 中设 messageMode
```

- 前端：http://localhost:8080
- 后端：http://localhost:8000
- 日志：`docker logs gochat-backend`（开发模式验证码打印在这里）
- 演示账号（seed 已初始化）：

  - 管理员：`18032353211` / `123456`（admin，is_admin=1，可进管理后台）


## 二、短信验证码（从用户场景出发的重点修复）

开发机 `configs/config.dev.toml` 里配置了阿里云 AK/SK/签名/模板（真实配置）。
容器环境（APP_ENV=docker）读取 `configs/config.docker.toml`，AK 为空。

**修复：两级降级策略（`internal/service/sms/auth_code_service.go`）**

1. `GOCHAT_SMS_DEV_MODE=true`（默认）→ 开发模式：验证码写入 Redis + 服务端日志打印
   （形如 `【开发模式】短信验证码 ... code=123456`），演示直接查日志取码即可，
   不依赖真实短信通道，也不花阿里云的钱。
2. `GOCHAT_SMS_DEV_MODE=false` 且 AK/SK/签名/模板齐全 → 走真实阿里云；
   配置缺失时自动降级为开发模式（不发短信也不报错）。

容器注入链路：`.env`（已 gitignore）→ docker-compose backend environment
（`GOCHAT_SMS_*` 已接上）→ `internal/config/config.go` 环境变量覆盖。
实测：`sendSmsCode` 返回 code=0，日志打印验证码，注册/登录走通。

> 安全说明：`configs/config.dev.toml` 含真实 AK，已被 .gitignore 忽略，勿提交版本库；
> 生产部署通过环境变量注入，不要在镜像/仓库里留密钥。

### 文件上传（本地磁盘存储，MinIO 为文档中的远期方向，未使用）

原实现：后端用**上传时的原始文件名**落盘、接口不返回路径；前端用本地文件名猜 URL。
导致：同名文件互相覆盖（演示时两人传同名图片头像互相串）、上传路径可预测、
文件名含 `../` 可目录穿越、三处"submit 后不等上传完成就发业务请求"的竞态。

修复：后端随机重命名落盘（时间戳+随机串+原扩展名）+ 扩展名白名单
（头像限图片；聊天文件限文档/图片/压缩包/音视频，拒绝 .html/.svg/.js 等可执行脚本）+
`filepath.Base` 防目录穿越 + 接口返回真实相对路径；前端统一用后端返回值拼 URL
（新增 `web/chat-server/src/utils/upload.js`），并改为"先上传拿路径、再提交业务请求"。
实测：上传返回 `/static/files/<随机名>.png`、静态可访问 200、`.html` 被拒、
`../evil.png` 未越界写出、文件消息 WS 收发正常。

## 五、演示时注意

- 手机/局域网访问：`http://<服务器IP>:8080`，前端自动指到同一 IP 的 8000；
  后端默认监听 0.0.0.0:8000 且 CORS/WS Origin 已放行 8080 端口任意 host。
- 注册/短信登录：查 `docker logs gochat-backend` 拿验证码（开发模式）。
- 需要真实短信：`.env` 置 `GOCHAT_SMS_DEV_MODE=false` 并确保 AK/签名/模板有效。
- 管理后台：用 is_admin=1 账号（admin）登录后，左下角"设置 → 管理员模式"。
